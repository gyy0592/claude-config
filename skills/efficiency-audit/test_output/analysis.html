What this demonstrates

The toy model (toy_model.py) has a deliberately slow __getitem__ that sleeps 4.0 s per sample to simulate slow disk reads. With num_workers=0 the main process serializes all reads. The audit pipeline's recommended fix is num_workers=4, persistent_workers=True, which pipelines reads across 4 worker processes.

Detected pipeline stages

  • Disk → CPU mem: SlowDataset.__getitem__ in toy_model.py — the bottleneck.
  • CPU compute: ToyMLP forward+backward; cheap (~µs per batch).
  • GPU compute: not used (CPU-only run).
