# Sub-skill 5 — Final report

## Prerequisites

- `report/efficiency/theoretical_limits.yaml` (sub-skill 1)
- `report/efficiency/analysis.html` (sub-skill 2)
- `report/efficiency/strategies.md` (sub-skill 3)
- `report/efficiency/experiments/*.log` (sub-skill 4)

## Goal

Produce `report/efficiency/final_report.html` — the single file the user actually reads. Everything else is supporting evidence. The final report must stand alone: a colleague reading just this HTML must understand what was wrong, what was changed, and what speedup was measured.

## Required sections (in order)

1. **Verdict banner** (top of page)
   - Color: red (#dc2626 background) if original verdict was RED ALARM, green (#16a34a) if GREEN.
   - Text: `"RED ALARM — speedup mathematically possible"` or `"GREEN — already saturated on <resource>"`.

2. **Machine summary** (one-paragraph)
   - 5-line digest from sub-skill 1 (GPU / CPU / IO / Memory ceilings).

3. **Current state** (one-paragraph)
   - Saturation table: GPU/CPU/IO percentages from sub-skill 2.
   - The detected bottleneck stage.

4. **Chosen improvements** (numbered list, top 3)
   - Each item: name, why, and the exact code diff in a `<pre>` block.
   - Diffs in unified format with `-` / `+` lines colored red/green.

5. **Before vs After** (the headline numbers)
   - Inline SVG bar chart of speedups (one bar per strategy, x-axis = strategy name, y-axis = speedup × from 1 to max).
   - A table below with: strategy, before_median_s, after_median_s, speedup, status.

6. **How to reproduce**
   - The exact shell command(s) to rerun validation:
     ```
     cd <repo>
     bash report/efficiency/experiments/run_all.sh
     ```
   - Note any environment dependencies (`pip install ...`, `nvidia-smi` available, etc.).

7. **Limitations** (honest disclosures)
   - "Static analysis was used; for residual sub-percent optimizations, run a real profiler."
   - "Speedups measured on a small slice; full-run speedup may differ within 10–20%."

## How to compose

1. `Read` `theoretical_limits.yaml`, `analysis.html` (just the verdict + saturation table), `strategies.md` (top 3), and each `experiments/*.log` (parse the `speedup` and `status` lines).
2. Compute the **combined speedup** by multiplying the individual speedups of strategies that compose orthogonally (most do; AMP + DataLoader compose, but two AMP variants don't).
3. Render the SVG bar chart with bar heights `(speedup_i / max_speedup) × 200`. Anchor the y=0 line at y=240.
4. Fill in the diff blocks from the actual code changes.
5. Write the file.

## Done condition

`report/efficiency/final_report.html` exists, parses as HTML, contains all 7 required sections, and at least one strategy shows `status: PASS`. Print a one-line summary to the chat:

```
Audit complete. Verdict: RED ALARM (was data-loading bound).
Recommended changes yielded 7.65x combined speedup (PASS on 3/3 strategies).
Full report: report/efficiency/final_report.html
```

Then the audit is done.
