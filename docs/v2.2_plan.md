## P36 — rules/ 分两层（先做这个）

**问题**：Claude Code 启动时把 `~/.claude/rules/*.md` 全部自动加载进 context。我们目前往那塞了 17+ 个文件（router/states/patches/prompt_enhancement/codex_adapter/fsm…），其中**只有一部分每轮真用得到**。剩下的 30-35KB 是 dead token。

更糟：`inject_router.sh` 跟 `transition.sh` 又会**动态注入**当前 state 对应的 router/states 文件——**双重加载**。

### 新分两层

**永远在 context（留在 `~/.claude/rules/`，auto-load）**：
- `facts_first.md` / `dispatch.md` / `recording.md` — 每轮真用
- `failure_stop.md` — 全程都可能触发
- `violation.md` / `lessons.md` — 全局 ledger（设计上就是 always-on）

注：subagent **不**继承 main 的 `~/.claude/rules/` auto-load。subagent 需要的规则由 `inject_subagent_prompt.sh`（P31 的新 hook）按 task_type 注入到 spawn prompt 里。`subagent_rules.md` 物理上可以留在 rules/（main 也看一眼便于知道有哪些规则），但**对 subagent 实际生效**是靠 inject hook 把 body 内容塞进它的 prompt。

**按需读（搬回 repo `content/rules/`，hook 用 `__CLAUDE_CONFIG_DIR__/content/rules/...` 引用）**：
- `router_*.md` × 6（router_BOOT / PREPARE / REFLECT / EXECUTE_LOOP / END + router.md fallback）—— inject_router 每轮选一个注入
- `states/*.md` × 5 — transition.sh 切换时 cat 当前的
- `patches/*.md` × 5 — 现在 AI 手 Read，P32 做完后由 hook 自动激活
- `prompt_enhancement.md` — 只 PREPARE state 用
- `codex_adapter.md` — 只 Codex 用
- `fsm.md` — 概览图，router 链接，AI 按需 Read
- `messages/*.md` — hook 模板，hook 显式 Read
- `workflow_config.yaml` — 常量配置，hook 读

### 具体改动

1. **`hooks/inject_router.sh`**：把读路径从 `~/.claude/rules/router_<STATE>.md` 改成 `__CLAUDE_CONFIG_DIR__/content/rules/router_<STATE>.md`（fallback 一样）
2. **`hooks/transition.sh`**：cat `states/<state>.md` 的路径换成 `__CLAUDE_CONFIG_DIR__/content/rules/states/<state>.md`
3. **`hooks/prepare_helper.sh`**：读 `prompt_enhancement.md` 改成 repo content/ 路径
4. **`set_claude.sh`** deploy 段：
   - **不再 copy** 上面"按需读"那批文件到 `~/.claude/rules/`
   - **只 copy** "永远在 context" 那 7 个
   - 现有的 `__CLAUDE_CONFIG_DIR__` sed 替换机制顺势用上
5. **`README.md` / `README.zh.md` / `docs/implementation.html`**：说明两层结构

### 工时
~80 LoC，5 个文件 + set_claude.sh，约 1.5 小时实施 + 30 分钟测试。

### 收益
~30-35KB token / session 起步省下来。规则改一处生效（不用 redeploy 文件）。

## P31 — Subagent FSM（task-type aware）

让 subagent 也走自己的 FSM，按 task 复杂度分级。Main 当调度者（上下文增长慢），sub 当执行者（可控、可监视、自我反思）。

### 前提（已验证 by haiku `ad7ba8a02d3aa8cf4`）
- UserPromptSubmit hook 在 subagent 上下文**会触发**
- hook input JSON 含 `agent_id` 字段（区分 main vs sub）
- subagent 跟 main **共享 session_id**（同一个 sid）
- 每个 subagent 有独立 transcript：`~/.claude/projects/<encoded-cwd>/<sid>/subagents/agent-<aid>.jsonl`
- jsonl 里有 `isSidechain: true` + `parentUuid` 标记

### 已确认事实（user 告知）
**subagent 启动时 `~/.claude/rules/*.md` 不 auto-load。** 它是 clean context，看不到 main 看到的规则文件。

→ **必须有 `inject_subagent_prompt.sh`**（复活 v1 的 PreToolUse:Agent hook，内容用 v2 版），在 Task 工具 spawn 时把规则塞进 prompt。这条**不是可选**，是 P31 的必需组件。

具体注入策略（按 task_type 分级）：

| Task type | 注入内容 |
|---|---|
| `simple_query` | 只注入 `subagent_rules.md` 的 B + D 条（写 summary + tag facts）。一两段，省 token |
| `focused_task` | A + B + C + D + G + H 条。中等 |
| `complex_task` | 全部 A-H + `facts_first.md` + `dispatch.md` + `recording.md` + `fsm.md` overview + 它要走的 state 对应的 `states/<state>.md`。最重 |
| `reviewer` | F 条 + `states/reflect.md` 的 reviewer 协议段 |

外加每个 subagent 都注入：
- `[YOUR_AID=<aid>]`
- `[YOUR_STATE_FILE=.barry_workflow/<sid>/agent_<aid>/state.md]`（如果 task_type 是 simple_query/reviewer 则不传，因为不走 FSM）
- `[TASK_TYPE=<...>]`

这个 hook 是 P31 的核心。

### Task-type 分级

| Task type | 例子 | FSM 走法 |
|---|---|---|
| `simple_query` | "看文件 X 第 50 行什么意思" | **不走 FSM**，单 EXECUTE，无 state.md |
| `focused_task` | "建 5 个 ledger 按 template"（P8 demo 的 EXECUTE subagent）| **mini FSM** BOOT → EXECUTE → END |
| `complex_task` | "诊断这个 bug，修，测" | **完整** BOOT → PREPARE → REFLECT → EXECUTE → END |
| `reviewer` | REFLECT rebuttal reviewer | **不走 FSM**，按现有 reviewer 协议 |

默认 `focused_task`。Main spawn 时 prompt 里加 `[TASK_TYPE=...]` 覆盖。

### 文件结构（嵌套在 parent main 下）

```
.barry_workflow/<sid>/
├── state.md              # main 的
├── action.md             # main 的
├── transitions.log
├── agent_<aid1>/         # subagent 1
│   ├── state.md
│   ├── action.md
│   └── transitions.log
└── agent_<aid2>/
    └── ...
```

### Subagent 怎么调 transition.sh？

主要难点：subagent Bash 工具的环境**没有 `CLAUDE_AGENT_ID` 环境变量**（binary 已确认）。所以 transition.sh 没法靠 env 自动认出 caller。

**解决方案 B（推荐）**：main spawn subagent 时，prompt 末尾告诉它：
```
[YOUR_AID=<aid>]
[YOUR_STATE_FILE=.barry_workflow/<sid>/agent_<aid>/state.md]
```

subagent 调 `bash transition.sh BOOT_DONE --state-file=<path> --reason="..."`，transition.sh 看 `--state-file` 参数就知道写哪。Main 调时不带这个 flag，默认写 `<sid>/state.md`。**零 race、零 env 依赖**。

### 实施 — 6 个文件 + 新 hook

1. **`hooks/_session_lib.sh`** ~20 LoC
   - 加 `agent_session_dir(cwd, parent_sid, aid)` helper

2. **`hooks/session_boot.sh`** ~30 LoC
   - 读 hook input 看有没有 `agent_id` 字段
   - 有 → 算 agent dir 路径，从 spawn prompt grep `[TASK_TYPE=...]`
   - simple_query / reviewer → 跳过 dir 创建
   - focused_task / complex_task → 建 `agent_<aid>/{state,action}.md`，YAML 里写 task_type

3. **`hooks/inject_router.sh`** ~15 LoC
   - 有 `agent_id` → 读 `agent_<aid>/state.md`（不是 main 的）
   - focused_task → 只注入 BOOT/EXECUTE/END router，跳过 PREPARE/REFLECT

4. **`hooks/transition.sh`** ~15 LoC
   - 加 `--state-file <path>` 参数处理
   - 没传 → 用 main 的 default
   - mini-FSM：只接受 BOOT_DONE 和 EXECUTE_EXIT 两种 event

5. **`hooks/state_enforce.sh`** ~10 LoC
   - 同样按 agent_id 分支读 state.md

6. **`hooks/inject_subagent_prompt.sh`**（新，**必需**）~50 LoC
   - 注册：`PreToolUse` with `matcher: "Task"`
   - 读 Task 工具调用的 prompt 字段，grep `[TASK_TYPE=...]`（main 必须传，没传默认 focused_task）
   - 根据 task_type 选要注入哪批规则（见上表）
   - prepend 到 prompt 前面
   - 注入 `[YOUR_AID=...]` `[YOUR_STATE_FILE=...]` 让 subagent 知道自己写哪
   - **subagent 把这段当成自己的"宪法"读** — 这是它唯一获得规则的渠道

7. **`content/rules/subagent_rules.md`** rewrite ~40 LoC
   - 按 task_type 分级（哪些 task_type 用 A-H 哪几条）
   - subagent **不递归**派 sub-sub reviewer

### 工时
~200 LoC（含可选的 inject hook），2.5-3 小时实施，1 小时测试（派 4 种 task_type 各一个 subagent 验证）。

### 测试
派 4 个 test subagent，确认：
- `simple_query`：**没**建 state 文件
- `focused_task`：建了 `agent_<aid>/state.md`，stage_history 走完 BOOT → EXECUTE → END（3 条），跳过 PREPARE/REFLECT
- `complex_task`：完整 5 状态走完
- `reviewer`：走 REFLECT 协议，没 state.md

## P35 — workflow_config.yaml 真 runtime source

**问题**：`workflow_config.yaml` 文件存在，里头写了 N=5 rebuttal 轮数、3 anomaly 失败上限等常量。**hook 没真读它**——值还硬编码在 hook 里，yaml 只是文档注释引用。改个值要改两处。

### 解决方案

最简单：在 `_session_lib.sh` 加一个**手写 mini yaml parser**（20 行 grep+sed，不用 yq 不用 python），读 dotted key 取值。

```bash
read_config() {
    local yaml="$1" key="$2"
    # key like "execute_loop.failure_budget"
    # parse path: split on '.', dive into yaml
    # use grep + sed to extract value
    ...
}
```

### 改动

1. **`hooks/_session_lib.sh`** 加 `read_config()` 函数 ~20 LoC
2. **`hooks/pretooluse_short_nudge.sh`**：`READ_THRESHOLD=$(read_config "$YAML" pretool_nudge.read_threshold)`
3. **`hooks/execute_loop_audit.sh`**：`FAIL_BUDGET=$(read_config "$YAML" execute_loop.failure_budget)`
4. **`content/rules/states/reflect.md`** subagent prompt 模板里的 `__N__` 占位符：main spawn reviewer 时 sed-replace 成 `read_config reflect.rounds_default` 的值

读不到 key 时用硬编码 fallback + stderr 警告。

### 工时
~50 LoC，1 小时实施 + 30 分钟测试（改一个 yaml 值，验证 hook 真用上）。
