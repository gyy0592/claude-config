# Barry's Workflow v2.1 — 实施计划

> 基于本会话讨论得出的 12 项工作。状态机骨架不变，重点是<b>规则重构 + 强制执行 + 自我进化基础</b>。

## 背景

v2 跑通后用户多轮讨论暴露的 12 个真问题（implementation.html §5 反思 + §6 TODO）：

1. **v1 包袱**：12 个 rule 文件里 50% 含 v1 cosplay 残留或冗余设计（p1_identity 已空 / p6_workflow REFLECT-A 6-row / index.md 重复 router）
2. **软约束失败**：状态机 90% 靠 AI 自律，没 hook 强制 transition 调用 / 状态切换提示 AI / 工具按 state 限制
3. **硬编码散布**：N=5 rebuttal / 3-anomaly 失败预算 / ≤100 char nudge 等常数写死在多个文件
4. **AI 乱写 [INFERENCE]**：当前 p2_facts_first 是文档要求，无机制强制 — AI 一念之差就直接出 inference
5. **router 不分 state**：每个 turn 注入同一段，无视 AI 当前在 BOOT 还是 EXECUTE
6. **跨 session 断**：重启 sid 变，旧 state 孤儿
7. **场景专属补丁混入 general**：Monitor cadence、anomaly 关键字这些其实是「长监控」「bug 调试」场景的事，混在 p3 / fsm 里污染 general 规则
8. **scenarios.html 悬空**：5 个理想场景 spec 没接到 seed
9. **lessons.md 不被强制查**：auto-loaded 但 AI 不一定回 user 前看
10. **session 文件平铺**：`.barry_workflow/` 下 state_X / action_X / reflection_X 几十个混在一起
11. **subagent 没自己空间**：subagent_rules.md 规定写 agent_&lt;aid&gt;/action.md 但 hook 不自动建目录
12. **templates/ 杂物**：9 个 v1 cosplay 文件（corporal / soldier / warning_board / 等）还在

## 任务清单

按依赖关系分批。前置必先做，后续可并行。

### 批 1 — 清理 + 重构（前置，~7h）

#### P11. 规则重构
- **删**：`p1_identity.md`（cosplay 已清完，规则无意义）/ `p6_workflow.md`（4-step 跟 state 机制重复，REFLECT-A 6-row 是 v1 包袱）/ `index.md`（router 本身就是查找表）
- **拆**：`p3_dispatch.md` 删 Monitor cadence 段 / `fsm.md` 切成 `states/{boot,prepare,reflect,execute,end}.md` 5 个文件
- **抢救**：从 `p6_workflow.md` 抢出 M6 3-failure stop 规则，独立成 `failure_stop.md`
- **合并**：`reflect_protocol.md` + `reflect_subagent_prompt.md` → `states/reflect.md`
- **改名去 p 前缀**：`p2_facts_first.md` → `facts_first.md`、`p3_dispatch.md` → `dispatch.md`、`p4_recording.md` → `recording.md`（state-machine 时代不需要数字编号）
- 工时 ~4h

#### P18. 模板清理
- **删 9 个 v1 cosplay 模板**：`corporal_situation.md` / `corporal_action.md` / `corporal_status.md` / `soldier_action.md` / `soldier_status.md` / `warning_board.md` / `reward_board.md` / `traitor.md` / `operation_log.md` / `status.md`（10 个其实）
- **保留 6 个**：`state_template.md` / `action_template.md` / `reflection_template.md` / `bitter_lessons.md` / `attempts_ledger.md` / `successful_fixes.md` / `goal.md`（看到 7 个，最后核对）
- **更新** `content/templates/README.md` 说明保留意图
- 工时 ~1h

#### P13. workflow_config.yaml 外置
- 新建 `~/.claude/rules/workflow_config.yaml`：
  ```yaml
  reflect:
    rounds_default: 5
    rounds_fallback: 10
    max_round_minutes: 15
  execute_loop:
    failure_budget: 3
    monitor_short: 5
    monitor_long: 60
  pretool_nudge:
    read_threshold: 3
    max_chars: 100
  prompt_reinforce:
    required_elements: [observable, cadence, reflection, completion]
  ```
- hook 脚本 + state docs 引用此 yaml 而不是硬编码
- 改阈值不动 .md / .sh
- 工时 ~2h

### 批 2 — 新机制（核心，~14h）

#### P12. INFERENCE_GATE 子状态
- 加强 `facts_first.md`：**非必要不给 [INFERENCE]**
- AI 真要写 [INFERENCE] → 触发 INFERENCE_GATE：
  1. 列已经做过的努力（Read 哪些文件 + WebSearch 哪些关键词）
  2. 缺数据 → 派 agent 补全 → 回 PREPARE / EXECUTE
  3. 真要写 → 强制 1 轮 rebuttal（reviewer 验证证据链）
  4. 通过 → 输出 [INFERENCE] 并永远带证据脚注
- 实现选择：EXECUTE_LOOP 内嵌迷你 REFLECT（不另开 state）或者第 7 个 state 平行 REFLECT
- 工时 ~3h

#### P15. state-aware router
- 当前 router 是 static，改成 hook 读 state.md → cat 对应 `~/.claude/rules/router_&lt;state&gt;.md`
- 模板示例 `router_EXECUTE_LOOP.md`：
  ```
  [ROUTER · state=EXECUTE_LOOP @ ts]
  
  你在 EXECUTE_LOOP — 做实际工作。
  
  本 state 必读（KV cache 没命中就 Read）：
    states/execute.md      — [PLAN]/[OBSERVE]、失败预算
    monitor.md            — 长任务节奏
    recording.md          — 写哪个 ledger
  
  常用：
    dispatch.md           — 复杂任务派 agent
    subagent_rules.md     — 派 agent 前看
  
  Always-on（每 state 都要遵守）：
    facts_first.md
  
  切换 state：
    bash ~/.claude/hooks/transition.sh EXECUTE_EXIT --reason=...
  ```
- 进 REFLECT 时换一套，列<b>禁止操作</b>（Edit / Write / 改文件的 Bash）
- 工时 ~3h

#### P16. 状态强制 hook
- 新建 PostToolUse hook（matcher=*）：每次工具调用后读 state.md，跟工具不符就警告
- 配合 P15 router 形成"硬约束"
- 例：state=REFLECT 期间调 Edit → 注入 "REFLECT 状态禁止 Edit，先 transition.sh REFLECT_DONE"
- 工时 ~3h

#### P14. patches/ 系统
- 新建 `~/.claude/rules/patches/` 目录
- 把 P11 抽出的场景专属补丁挪过来：
  - `patches/long_monitor.md`（cadence 三档 + Monitor 5-60-60+ 节奏）
  - `patches/bug_debug.md`（anomaly 关键字白名单 + 失败预算 3）
  - `patches/perf_debug.md`（baseline 必测 + 一次改一个变量）
- schema 见 `docs/big_picture.md §3.3`
- BOOT hook 扫 patches/，router 注入时按 `applies_to` 过滤
- 工时 ~5h

### 批 3 — 文件组织 + 收尾（~5h）

#### P22. session 子目录
- 当前 `.barry_workflow/{state,action,reflection,nudge_counters}_&lt;sid&gt;.{md,json}` 平铺
- 改成 `.barry_workflow/&lt;sid&gt;/{state,action,nudge_counters}.{md,json}` + `reflection_*.md`
- subagent 用 `.barry_workflow/&lt;sid&gt;/agent_&lt;aid&gt;/{state,action}.md`（解决 v2 issue 11）
- 修改：`session_boot.sh` / `transition.sh` / `prepare_helper.sh` / `execute_loop_audit.sh` / `pretooluse_short_nudge.sh` 全部 path 替换
- 加 helper 函数：`session_dir() { echo "$CWD/.barry_workflow/$SID"; }` 各脚本 source 一下
- 工时 ~2h

#### P17. 跨 session inherit
- `session_boot.sh` 检测 `.barry_workflow/` 下有旧 sid 子目录 → 询问 user 或 auto-pick latest
- 复用模式：写 `inherited_from: &lt;old_sid&gt;` 到新 state.md，初始 `cache_hit_map` 从旧的拷贝
- 工时 ~2h

#### P21. lessons 常态化
- router always-on 段加一行：「回答 user / 输出文件前用 lessons.md tags grep 检查个人偏好命中」
- 工时 ~1h

### 批 4 — 验证（~6h）

#### P19. P8 demo（user 监督）
- 跑 Qwen-0.5B + 100 GSM8K + activation hook + 利用率验证
- 验证整个 BOOT → PREPARE → REFLECT → EXECUTE → REFLECT → END 流程
- 期间观察哪些 state 转换实际被 AI 跳过、哪些 hook 真触发
- 产出 bitter_lessons + lessons 条目
- 工时 ~4h

#### P20. scenarios ↔ patches 对齐
- 把 `docs/scenarios.html` 5 个场景的 cadence 公式 / REFLECT 轮数转成 `patches/*.md` 的 `applies_to` 触发器
- 让 seed rule 跟 spec 一一对应
- 工时 ~2h

## 总览

| 批次 | 内容 | 工时 | 重要性 |
|---|---|---|---|
| 1. 清理 | P11 / P18 / P13 | 7h | 必须，前置 |
| 2. 核心机制 | P12 / P15 / P16 / P14 | 14h | 核心 |
| 3. 组织 | P22 / P17 / P21 | 5h | 体验提升 |
| 4. 验证 | P19 / P20 | 6h | 落地校验 |
| **合计** | | **32h** | 4-5 工作日 |

## 落地顺序建议

**最小可用增量**：批 1 全做（清出干净 surface）→ P22 改文件组织 → P15 + P16（hard-constraint state-aware router）→ P19 demo 验证

这条路径 ~16h 就有"v2 + 状态强制 + 文件组织清"的可用产品。

剩下 P12 / P14 / P17 / P20 / P21 可以再迭代一遍 v2.2。

## 跟 v2 的差异

| 维度 | v2 | v2.1 |
|---|---|---|
| 规则文件数 | 12（含 v1 残留） | ~8 顶层 + 5 state-specific + 3-5 patches |
| router | 1 个 static | state-aware 5 个 router_&lt;state&gt;.md |
| 硬编码 | 散布多文件 | 集中在 workflow_config.yaml |
| 状态强制 | 软（AI 自律） | 硬（PreToolUse + PostToolUse 联合校验） |
| session 文件组织 | 平铺 | 每 sid 子目录 |
| 跨 session | 断 | inherit |
| 补丁系统 | 设计未实现 | 3 个示例补丁 + 加载机制 |
| [INFERENCE] 约束 | 文档要求 | 强制 GATE 子状态 |
| 验证状态 | smoke-test | P8 demo 端到端跑通 |
